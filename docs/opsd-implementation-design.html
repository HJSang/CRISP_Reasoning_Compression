Implementation choices and limits

  • --loss-type opsd_loss is separate from native sampled-token OPD. Do not enable --use-opd. The initial recipe requires disabled advantage computation, dense canonical LoRA, PP1/CP1, fixed microbatches and a frozen base checkpoint whose non-adapter parameters match the actor.
  • Teacher snapshot initialization zeros every canonical adapter factor. A base-weight equality check rejects accidental checkpoint changes. Each scoring call restores actor weights and train/eval mode in finally, before student autograd. Teacher targets are keyed by sample index, rollout ID, response IDs, vocabulary interval and temperature.
  • Normalize distributions over the HF output-head vocabulary, not tokenizer.vocab_size. Remove only extra Megatron padding columns. BF16/FP16 logits are promoted to FP32 for distribution/loss math. Literal low-precision author arithmetic still needs its own comparison.
  • Default β=0, loss temperature 1.1, pointwise contribution clip 0.05; CLI clip 0 disables clipping. Sampling temperature/top-p/top-k are separate. The clipped sum can be negative, as in the source implementation.
  • The reduction is the valid-token mean within each reference microbatch, followed by Megatron accumulation and DP averaging. The global-token alternative is deliberately rejected in this version. Zero-valid-token microbatches fail instead of silently changing the denominator. Larger packed microbatches do not reproduce the author's right-padded prompt behavior; the supplied pilot uses microbatch one.
  • Default CPU target limit: 8 GiB per worker; target payload per microbatch: 1 GiB. These limits exclude model weights, optimizer state, activations, full prompt logits and loss temporaries. Reject overlong sequences and oversized caches; never truncate only the teacher or silently switch to top-k.
  • The first generator reads a raw problem and metadata.solution. Dataset-level chat templating is rejected. It masks response tokens equal to the tokenizer's PAD ID, matching the original label rule. PAD IDs inside rendered prefixes or before non-PAD response IDs are rejected because packed attention cannot reproduce those attention-mask holes. This rejects Qwen3 EOS-as-PAD; native distinct PAD/EOS is supported. Evaluation does not require or use the solution.

Integration fix found by the live pilot

An initial complete rollout reached teacher scoring and failed before an optimizer update: launch arguments declared 152,064 padded vocabulary columns, while Bridge constructed the 151,936-column HF output head. The scorer now derives its shard width and target-memory budget from the actual model, verifies vocabulary-parallel output, and checks each returned logit shard against that width. It still normalizes over the real HF vocabulary. A TP2 regression deliberately sets inconsistent launch-time padding and passes two tiny-model updates, unchanged teacher distributions and exception restoration; maximum HF teacher log-probability error is 0.003551. The corrected full 4B run subsequently completed both requested updates.

3. Match the actual loss, including its quirks

p = softmax(student_logits / τ)
q = stop_gradient(softmax(teacher_logits / τ))
d[t,v] = q[t,v] · (log q[t,v] − log p[t,v])          # β = 0

L = Σ[t,v] mask[t] · min(d[t,v], c) / Σ[t] mask[t]  # clipping enabled
L = Σ[t,v] mask[t] · d[t,v] / Σ[t] mask[t]          # unclipped

The inspected loss function clips each vocabulary contribution before summing, has no extra τ² multiplier, and uses valid-token normalization for labeled “batchmean.” β=1 selects reverse KL; interior β uses its specified weighted mixture. Negative individual contributions remain negative, so the clipped sum need not be nonnegative. Do not silently replace this with clipping a summed token KL, PPO clipping, or response-mean reduction.

Distributed normalization needs a separate proof. With unequal valid-token counts, averaging independently normalized reference microbatches/ranks differs from a global valid-token mean. First match the original grouping, DP topology and accumulation schedule. Then test a global-token reducer against an independently aggregated oracle as a separate, explicitly named behavior. Do not let Miles' default sum-of-response-means or dynamic rebatching choose the objective implicitly.

For TP, normalize across the complete real vocabulary, excluding padded vocabulary entries before log-sum-exp. Keep student normalization differentiable, reduce teacher and student normalizers across TP, clip each local vocabulary element, then sum across TP exactly once. No full-vocabulary all-gather is required. Verify backward scaling as well as forward values; ordinary detached collectives are insufficient for student gradients.

Separate SGLang teacher versus Megatron forward-only teacher

Recommendation for this design: begin with the Megatron teacher on the training workers for exact full-vocabulary, fixed-base-teacher parity. Treat a separate SGLang scorer as a second backend to benchmark after the target contract works. SGLang becomes particularly attractive for compact sampled-token targets, independent teacher scaling or multiple teacher services. This is an engineering recommendation from source inspection and payload arithmetic, not a measured throughput result.

Both choices consume the same T + Y input from the TITO contract: privileged teacher prefix plus the exact student response IDs. Both can perform teacher-forced scoring without generating another response. There are two independent decisions: engine (SGLang or Megatron) and placement (shared training workers or dedicated teacher workers). The table compares a dedicated SGLang service with Miles' existing shared-worker Megatron snapshot/switch pattern. A dedicated Megatron teacher could also overlap work, but would require its own resources and target transport.

The loss determines the transport requirement. With B=32, R=1,024 and V=151,936, one FP32 score per response token is 128 KiB; top-128 FP32 scores plus int32 IDs are 32 MiB; a dense FP32 teacher distribution is 18.55 GiB. These are binary payload sizes before metadata, copies or JSON overhead, not runtime estimates. The dense teacher tensor is required at the student loss for the proposed exact objective; moving the scorer to a server does not make that tensor small. Top-k renormalization changes the objective and cannot be introduced merely to make transport convenient. At fixed R,V, TP/DP partitions distribute this total rather than removing it.

The Megatron correctness path also pays for the dense targets: its proposed CPU store moves targets off GPU and back for the student microbatch. It avoids remote serialization/transport, not all memory traffic. The existing normal weight-backup implementation uses pinned CPU copies and synchronized restores; these costs belong in the benchmark. A frozen base with LoRA suggests a future optimization by switching adapter state instead of all weights, after exact base-teacher validation.

A possible SGLang optimization, outside the first implementation: export the teacher's final hidden states at the aligned prediction positions, then apply the frozen teacher output head and vocabulary normalization locally on the training workers. This changes wire volume from O(BRV) to O(BRH) when hidden width H is much smaller than vocabulary size V, while retaining full-vocabulary computation locally. It needs the exact teacher head, post-normalization hidden-state semantics, all required response positions and layout/precision parity; a generic hidden-state API flag does not establish those guarantees. It shifts projection work and head storage to the trainer and creates a hybrid numerical path. Evaluate it only after dense-target parity, rather than treating the naive dense payload as an unavoidable network lower bound for every architecture.

Strict on-policy execution limits overlap. Within a rollout batch, a dedicated scorer can work as completed student samples arrive. It cannot score unknown future response tokens. Rolling out the next batch using an older student while an optimizer update is underway introduces policy lag unless an explicitly different algorithm handles it. Use rollout and teacher version checks for either backend; service independence is not permission to relax freshness.

Serving speed is not scoring speed. Here the whole T + Y sequence is already known. The workload is causal forward scoring and vocabulary projection, not iterative teacher decoding. Measure required response-position distributions, serialization and end-to-end training throughput; do not infer a win from generation tokens per second or speculative-decoding speedups. Repeated teacher prefixes may help caching, but a different privileged prefix does not allow reuse of the student's response KV states.

What the pinned Miles code provides today

The SGLang scoring request sends token IDs with max_new_tokens=0 and requests logprobs, optionally selected IDs or top-k. The current caller supplies sample.tokens, so separate PI prefixes must still be added. SGLang's documented native API supports token-ID inputs and selectable logprob fields; that is not proof that the pinned Miles path returns the full distribution we need. Pin and test the serving version and export format.

The Megatron actor has distinct reference and teacher snapshots, switches to the teacher, computes scores, and restores actor weights. Its forward-only function runs without gradients in evaluation mode and exposes an output callback. The existing teacher call is inside advantage computation and uses ordinary rollout inputs. Our direct OPSD objective needs its own explicit teacher prepass, independent of advantage computation. The distillation teacher is a separate logical role from a reference-policy KL penalty.

For either backend, return the same mathematical target: log q = log_softmax(teacher_logits / loss_temperature) over the real vocabulary at response positions, with checkpoint/version, offsets, masks and dtype recorded. Do not assume a generation sampling temperature controls returned input logprobs. The existing request's sampling temperature zero is not an implementation of loss temperature 1.1. A complete base-temperature logprob vector can be re-tempered and renormalized; one selected logprob alone does not determine the new normalizer. Validate the exact API behavior on synthetic logits or a small reference model.

A fair backend comparison after the first implementation

  1. Fix the workload. Feed identical teacher prefix IDs and student response IDs from an immutable tape to both scorers, using the same base checkpoint, tokenizer, precision and loss temperature. Exclude generation from scorer-only timing and include it in end-to-end timing.
  2. Separate accuracy from speed. Compare aligned teacher distributions and the resulting loss/student gradients using one common student computation. Add a same-weights, no-PI control to measure SGLang-versus-Megatron engine differences before interpreting PI corrections. Keep original/HF checks as the independent oracle.
  3. Account for all resources. At a fixed total GPU budget, measure teacher forward, weight switches, target-copy/serialization/transfer time, peak GPU and host memory, trainer idle time, completed updates per hour and aggregate GPU-hours. Also report scorer-only capacity; dedicated teacher GPUs are not free speedup.
  4. Compare the same output contract. First compare dense targets against dense targets. Report sampled-token or top-k variants separately with their changed objective/approximation. Keep cold-cache and repeated-prefix measurements separate, and test version invalidation.
  5. Decide from the report. Keep Megatron for the first parity baseline. Adopt the SGLang backend if measured end-to-end gains justify its target-transport and consistency costs. No new GPU work or full run is authorized by this comparison.

Bound memory honestly

Start with a correctness path that writes each teacher response block to a worker-local CPU target store immediately. Preserve FP32 target values for the FP32 parity contract, with sample ID, rollout/model version, temperature, vocabulary interval and response indices. Stage only the active student microbatch's targets on GPU, retaining them through its backward pass before release. Avoid caching the whole rollout batch on GPU or passing dense targets through the object store.

This limits target residency to a microbatch, but does not remove total target storage cost. At batch 32, vocabulary 151,936 and FP32, response targets alone occupy about 18.55 GiB at 1,024 tokens or 148.38 GiB at 8,192 tokens before TP/DP partitioning. Model logits, activations, copies and optimizer state are additional. Enforce CPU-cache and GPU-microbatch budgets and reject oversized configurations. An ordinary chunked loss forward can retain every target chunk for autograd, and does not prevent full prompt-logit materialization. Measure both peaks; true bounded chunked backward would be a later, independently gradient-validated optimization.

After parity, optimize scoring by bounded prepass groups or a separate frozen scorer if needed, with identical-target tests. Do not quietly introduce top-k truncation or reduced target precision as a memory fix. These change the validated numerical contract.

5. Alignment, frozen teacher and LoRA equivalence

Two prefixes, one exact response

The contract is the same response token IDs under separately constructed prefixes. Chat templating is a function over messages, not a string of template tokens appended after a raw question. Construct the student's question-only messages and the teacher's question-plus-PI messages, then render each with its declared chat-template settings and assistant generation boundary. This follows the Transformers chat-template contract. Tokenize once; if rendering to text first, avoid adding duplicate special tokens during subsequent tokenization.

# Conceptual single-example contract; S and T contain all prompt/control IDs.
S = template_and_tokenize(student_messages)
T = template_and_tokenize(teacher_messages_with_PI)
Y = student_generate(input_ids=S).output_token_ids

student_input_ids = S + Y
teacher_input_ids = T + Y     # identical Y; score it under the teacher context

p_t(v) = student(v | S, Y[:t])
q_t(v) = teacher(v | T, Y[:t])

student: [ question + chat/control tokens ] [ y0  y1  y2 ... ]
teacher: [ question + PI + chat/control tokens      ] [ y0  y1  y2 ... ]

The teacher evaluates the next-token distribution along the student's trajectory. It does not generate a replacement response for this loss. A causal forward over the whole teacher sequence supplies all these distributions at once; the distribution for y_t must not see y_t or later response tokens. Full-vocabulary OPSD compares p_t(v) and q_t(v) over the shared vocabulary; gathering only the probability of y_t supplies a different, sampled-token signal.

Alignment is by response index, not absolute position. For an unpadded example, let Ls=len(S), Lt=len(T) and R=len(Y). Logits at position Ls-1+t and Lt-1+t both predict y_t, for t=0...R-1. With prefix lengths 5 and 8, the aligned logit positions for three response tokens are [4,5,6] versus [7,8,9]. These different position IDs are expected. The response equality invariant is student_input_ids[Ls:] == teacher_input_ids[Lt:] == Y. Packed batches use per-example offsets and sequence boundaries; padded reference batches need their exported masks and layout.

How this should fit Miles TITO

  • Keep the rollout token stream authoritative. Preserve the actual student prompt IDs sent to the engine and its raw returned response IDs. Decode only for display. Do not decode and re-encode Y or re-render a complete assistant message from response text to construct the scoring sequence. Include the engine-returned terminal tokens and carry explicit validity/termination metadata; do not synthesize EOS after a length cap.
  • Create a separate teacher scoring view. Store student_prompt_ids, teacher_prompt_ids and response_ids logically; keep Miles' existing sample.tokens equal to the student sequence. Build teacher inputs from its own prefix plus the shared response. Teacher KV states must be computed under that prefix; student response KV states are not interchangeable.
  • Respect session ownership. Miles' TITO session path preserves accumulated IDs while extending a conversation and validates compatible message history. PI insertion changes earlier context, so it belongs in a fresh teacher scoring input, not an edit to the student's existing session. Model-specific boundary handling for later turns does not license re-tokenizing the generated suffix for this single-turn loss.
  • Declare compatibility. Exact shared response IDs and vocabulary-wise KL require the same token-ID semantics. Pin tokenizer revision, special tokens, resolved template and thinking options. Compare Miles' fixed TITO template against the original collator explicitly; the same model name does not prove identical rendering.
  • Validate the reference without hiding differences. Compare rendered prefixes, raw completion IDs, response offsets, masks and terminal-token treatment on batch-one and unequal-length fixtures. If packed Miles and the literal reference differ, preserve a minimal reproducer and label any corrected protocol separately from strict reference equivalence.

Inspected Miles paths: raw token accumulation, session trace to sample, and session prefix preservation. The current native OPD teacher request sends sample.tokens; it does not yet provide this separate privileged prefix. These are source findings, not completed runtime validation.

Adapter and teacher-state equivalence

  • Frozen base teacher. The author implementation disables student LoRA adapters for the teacher pass. A Miles snapshot is equivalent only if every adapter contribution is zero and the base weights match. Verify teacher logits against the unadapted HF base both before and after a student update. Merely loading base weights into a model with live adapters is insufficient.
  • Canonical adapters. Use Miles' existing canonical_lora mapping for independent Q/K/V and gate/up projections. A fused shared-rank adapter is not generally equivalent to the HF recipe. Import identical adapter tensors, validate projection permutations and alpha/r scaling, and compare effective weight updates after export—not unrelated raw tensor layouts.
  • No teacher autograd. Teacher targets and weights remain detached. Check that teacher parameters have no gradient and do not change after an optimizer step. Do not swap weights between a student forward and its backward.
