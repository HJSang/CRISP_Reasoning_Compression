What we know, and what we still need

The bounded correctness pilot passed one full Qwen3-4B HF reference diagnostic and two Miles TP2 updates. All eight Miles response tapes match the original OPSD teacher input IDs and masks. The HF diagnostic's maximum loss error was 4.20×10−9, with zero logit-gradient error.

This validates the implemented path within its tested scope. It does not establish learning gains, original-trainer reproduction, or mapped HF↔Megatron update parity. Three of eight Miles responses hit the 1,024-token cap; eight held-out questions were prepared but never evaluated. Training timings from two short updates cannot forecast native-thinking evaluation cost.

Three deliberate changes from the compatibility pilot: provisionally disable teacher thinking to match the now non-thinking student, propose an 8,192-token training response budget, and disable the original per-vocabulary contribution clip for the scientific objective. All study arms share these settings. Preserve the original off/on, 1,024-token, clipped recipe as a separate reference check.

Separate PI from checkpoint effects

At the same student-generated response prefix, score the complete vocabulary with one tokenizer, template mode, scoring temperature and backend:

p   = current student θ, no PI
r   = frozen base teacher φ₀, no PI
q_c = frozen base teacher φ₀, with context c
s_c = current student θ, with context c

C_c = log q_c − log r                 PI/context correction
K   = log r − log p                   checkpoint correction
G_c = log q_c − log p = C_c + K        raw OPSD correction
I_c = C_c − (log s_c − log p)          checkpoint × context change

q[a,b] = softmax(log stopgrad(p) + a C_c + b K)
q[0,0] = p          q[0,1] = r
q[1,0] ∝ p q_c/r    q[1,1] = q_c

All target quantities are detached and recomputed once before each optimizer update. The transported target q[1,0] applies the frozen teacher's PI correction to the current student. Use log-space normalization across all vocabulary shards; do not divide small floating-point probabilities directly. This is an exact algebraic factorization, not proof that separately prompted LLM calls define a coherent Bayesian joint distribution.

Thinking-mode assumption: the four-distribution decomposition below uses thinking off for p, r, q and s. This is the provisional teacher-scoring choice, pending preference. If teacher scoring is kept thinking-on as in the original recipe, log r−log p also contains a mode effect even at identical checkpoints. Add a separately scored same-mode baseline and an explicit mode contrast before labeling that gap checkpoint drift; do not run the current factorial matrix unchanged.

At initialization, θ=φ₀, so K=0 and the key arms collapse. First produce a common θ₆₄ using 64 raw worked-solution OPSD updates, then branch every arm from that checkpoint with fresh identical optimizer state. Keep φ₀ frozen. The conclusion is conditional on this warm-up history; it is not a universal statement about teacher age.

For the unchanged baseline, skip optimizer steps entirely. A nominal zero loss with inherited Adam moments can still change parameters. In diagnostics, identical weights and identical no-PI prefixes must give zero correction within numerical tolerance.

The unclipped objective is a deliberate scientific baseline: its exact KL has a clear zero point and no negative clipped sums. The original author implementation clips individual vocabulary contributions at 0.05, which is not clipping a summed token KL. Before the study, test both settings against the pinned reference on the same short tapes; retain the clipped result as compatibility evidence, not as a pooled scientific arm. This study is not an exact reproduction of the author's recipe.

Score p,r,q,s with the Megatron forward-only path to reduce backend confounding. SGLang generates student trajectories and evaluates immutable checkpoints. Sampling filters define the visited-prefix distribution; full-vocabulary KL is still computed exactly at those prefixes. A sampled next-token log-ratio is not that KL.

Does training sampling match original OPSD?

The three explicit sampling settings match: the pinned original Qwen3-4B launcher sets temperature 1.1, top-p 0.95 and top-k 20. The trainer forwards these to vLLM sampling. Generation top-k is separate from top_k_loss, whose default uses the full vocabulary.

Data, PI construction, and leakage controls

Use the pinned author math dataset at revision 1f33e9dc2e8a1c639ca74f8024ad4a9f1f5eae62 (29,434 loaded rows). Build a new study manifest; the pilot's first-32/next-8 split is only a wiring fixture. Do not filter by the dataset's model-relative correct field.

  1. First remove problem groups overlapping the named external benchmarks; normalize and deduplicate exact problems, cluster near-duplicates and shared problem templates, then hash-order the remaining groups into disjoint pools. Reserve 1,024 groups for warm-up, 4,096 adaptation, 256 profiling, 2,048 utility, 256 development and 1,024 final test (8,704 total). These are requested pool sizes, not a completed split; insufficient eligible groups stops preparation.
  2. Keep related problem instances together across pools. Stratify adaptation and utility blocks by coarse topic/difficulty, without sharing duplicate/template groups. Each pilot block uses 16 adaptation questions and 64 unique utility questions; eight utility panels are disjoint. The same panels serve A and B.
  3. Answer-only PI uses the canonical Answer field. Require a parsable reference final answer that matches it for worked-solution PI; audit reasoning on a fixed sample. Final-answer agreement does not verify every reasoning step. Quarantine ambiguous labels before branch outcomes are observed.
  4. Choose unrelated examples from the adaptation pool, with a different duplicate/template group and a similar token-length bin (within ±10% where available). Exclude final-test and utility answers from all PI construction. Log unmatched exclusions before sampling blocks.
  5. Generate evaluation requests from a prompt-only export. Store answers separately for grading. Pin the math parser/equivalence checker and its version; manually audit 50 fixed examples, including malformed and ambiguous outputs. Report parse failures and timeouts; missing final answers count as incorrect.

Student and teacher chat templates are applied once to different prefixes, then receive the identical response-ID suffix. Score the first response token at each prefix's last logit row. Include genuine generated EOS; do not invent EOS at the response cap. Keep cap-hit samples in training/evaluation and report their rate. A response cap is a compute budget, not evidence of a completed derivation.

This internal holdout estimates adaptation gains on this data distribution. It does not establish absence of pretraining contamination or transfer to independent math benchmarks, code, or frontier models. Final-test data stay sealed during feasibility and method selection.

Evaluation datasets and the 30,000-token budget

All evaluation uses exactly 30,000 maximum new tokens, including thinking, final-answer text and any generated stop token. This replaces the former 8,192-token evaluation proposal. Training remains capped at 8,192. Evaluation keeps thinking on, temperature 0.6, top-p 0.95, top-k 20 and min-p 0, without PI or tools.

Use a separate evaluator configured for a 32,768-token total context. Require every fully templated evaluation prefix to fit within 2,768 tokens, leaving the full 30,000-token response allowance. Fail preparation if a benchmark cannot fit; do not truncate prompts, silently shorten responses or omit long questions. The pinned Qwen3-4B configuration has max_position_embeddings=40960 and no RoPE scaling; this proposal stays within the model card's native 32,768-token context and needs no new scaling regime. The training engine's 12,288-token total limit must not be inherited by the evaluator.

The earlier draft specified only an internal holdout, with external benchmarks left unnamed. Use two explicit evaluation tiers:

  1. Paired adaptation utility: 512 unique questions from the disjoint internal utility pool, organized as eight panels of 64. Evaluate each of the 64 short branch endpoints on its panel and evaluate the shared unchanged baseline once per panel. This remains 4,608 completions at 30,000 tokens each; it is the first feasibility study's learning metric.
  2. External benchmark suite: the six named datasets below, evaluated on the prespecified longer-run endpoints and their unchanged starting checkpoints in the separately reviewed confirmation stage. What will decide the next experiment?

PI utility

For each context and block, predict U_context−U_noPI using features measured before adaptation. Start with two predeclared PI features: mean full-vocabulary D_KL(q_c || r) and its difference between correct and incorrect initial student responses. Record that the latter is unavailable for all-correct/all-incorrect blocks; keep those blocks. Compare against difficulty, response length/cap rate, raw OPSD divergence D_KL(q_c || p) and checkpoint drift. Token curves and entropy/EOS changes are secondary diagnostics.

In this eight-block batch, plot paired outcomes and estimate variance; do not fit and announce a successful selector. A later, separately reviewed study needs new discovery and held-out blocks, a frozen low-capacity predictor, grouped validation, and a comparison of its chosen PI against fixed worked-solution PI and a compute-matched random choice. Training and evaluation of the selector must not reuse outcome labels.

Checkpoint effects

Report B10−B11, BS−B11 and the full factorial contrast, plus every arm's absolute accuracy, response length, cap rate, entropy and pre/post-clipping update norms. If transported PI wins, inspect a development-only matched-update-norm comparison before concluding the checkpoint anchor is harmful. If synchronized PI wins, distinguish freshness from amplification or collapse before testing EMA.

Pair by problem and block, and bootstrap whole blocks with their shared controls; do not treat tokens, related problems, or duplicated cross-node controls as independent samples. Report feasibility intervals as exploratory. In confirmation, report training seeds separately and use paired problem-group uncertainty with prespecified multiplicity control for B10−B11 and BS−B11.

A +2 percentage-point target is a desired practical effect, not a power guarantee. For illustration, a paired comparison with discordance 0.20 needs roughly 3,920 independent questions for 80% power at two-sided 5% significance to detect 0.02, before clustering or multiple comparisons. Estimate actual discordance and training variability from the pilot before sizing confirmation.

Conditional next stage, after reviewing feasibility

Run two independent follow-ups concurrently: A expands PI-utility prediction to new blocks; B runs longer checkpoint comparisons. Replicate selected comparisons at training seeds 29 and 43 with their own common warm-ups and swapped node assignments. Freeze the loss, prompt, length and selection rules before consuming final test. Use the pinned six-dataset external suite on the prespecified endpoints and their unchanged baselines. Its repeated samples and costs belong to the confirmation-stage review, not the 4,608-completion feasibility count. Add a separately pinned retention panel before claiming general improvement.

Only then move to code transfer, MOPD routing, an RL-trained PI generator, teacher EMA schedules, or a larger publicly available reasoning model. Qwen3-4B feasibility cannot establish behavior on frontier GLM, Kimi or DeepSeek models. No automatic frontier run or open-ended hyperparameter sweep is included.
