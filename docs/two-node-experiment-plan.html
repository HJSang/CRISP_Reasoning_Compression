What we have learned · October 9, 2026

TL;DR: the tested Miles implementation preserves the original OPSD token/loss contract, and individual training and evaluation jobs work. We have not established learning gains, full HF/Megatron update equivalence, or benefits from transported PI. Full-parameter readiness work and monitoring have resumed on four workers.

The research comparison must separate three changes

The raw teacher–student log-probability difference combines the effect of PI with the effect of using a different checkpoint: log q − log p = (log q − log r) + (log r − log p), where p is the current unprivileged student, r the frozen unprivileged teacher, and q that same frozen teacher with PI. The transported target normalize(p q/r) provides a concrete intervention for testing the PI correction separately. Its normalization and algebraic endpoints passed the implementation checks; whether it teaches better remains unknown.

Thinking mode is another confound. The pinned original recipe uses a non-thinking student and thinking-enabled teacher. Our mechanism study makes both non-thinking, so a PI contrast does not simultaneously switch that mode. Equal student and teacher checkpoints make the checkpoint term zero at initialization; the planned common warm-up is needed before the checkpoint comparison becomes informative. This factorization is algebraic and does not establish that separately prompted LLM distributions form a consistent Bayesian joint.

Exact inputs and loss agreement are necessary, but insufficient

Student and teacher need separately templated prefixes followed by the identical generated response IDs. All eight audited live trajectories matched the pinned author input builder. The original/HF loss diagnostic agreed to 4.20×10−9, with zero logit-gradient difference. However, the mapped 4B BF16 optimizer-update test still fails its declared tolerances. These are different validation levels; token or loss parity cannot substitute for update parity.

The current scientific objective is unclipped full-vocabulary forward KL with temperature 1 and equal response weighting. That is a controlled baseline choice, not a finding that forward KL is optimal. Mode, clipping and sampling differ from the original recipe, so the planned study is not a reproduction of the published training result.

Execution details can change the apparent experiment

Loading an adapter with fresh Adam state also requires refreshing the optimizer’s FP32 master parameters; otherwise an update can overwrite the loaded weights with initialization. We fixed that path and checked reload training. We also corrected loss metric weighting across microbatches; the logging fix does not change autograd. All branches need the same effective batch and reduction to keep memory tuning from changing sample weights.

The controlled 4K replay supports microbatch two: substantially less memory than four for a small training-time difference. The 4K generation profile rarely truncates, while 8K AIME evaluation frequently does. Some sampled cap-hit responses repeat, so a longer budget may not cure them. Evaluation concurrency improved single-GPU throughput, but altered sampled outputs even with fixed request seeds; those profiles cannot be interpreted as accuracy improvements.

Filtering also matters for PI quality. The source contains unparsed or disagreeing final answers, solved-prompt artifacts and duplicate groups. Automated filtering and final-answer checks do not establish that every reference derivation is sound; the final reasoning audit is incomplete.

Claims we cannot make yet

We do not yet know whether PI corrections predict useful student learning, whether worked solutions beat answer-only PI, whether checkpoint anchoring helps or hurts, or whether transported/current-student PI beats frozen-teacher OPSD. There is no MOPD combination result or frontier-model evidence: live validation used Qwen3-4B. No scientific warm-up or full branch matrix has run. Validating the revised full-parameter, 16K evaluation protocol and resolving numerical agreement, then completing data and execution validation, remains necessary before those comparisons.

Separate PI from checkpoint effects

At the same student-generated response prefix, score the complete vocabulary with one tokenizer, template mode, scoring temperature and backend:

p   = current student θ, no PI
r   = frozen base teacher φ₀, no PI
q_c = frozen base teacher φ₀, with context c
s_c = current student θ, with context c

C_c = log q_c − log r                 PI/context correction
K   = log r − log p                   checkpoint correction
G_c = log q_c − log p = C_c + K        raw OPSD correction
I_c = C_c − (log s_c − log p)          checkpoint × context change

q[a,b] = softmax(log stopgrad(p) + a C_c + b K)
q[0,0] = p          q[0,1] = r
q[1,0] ∝ p q_c/r    q[1,1] = q_c

All target quantities are detached and recomputed once before each optimizer update. The transported target q[1,0] applies the frozen teacher's PI correction to the current student. Use log-space normalization across all vocabulary shards; do not divide small floating-point probabilities directly. This is an exact algebraic factorization, not proof that separately prompted LLM calls define a coherent Bayesian joint distribution.

Confirmed thinking-mode choice: student generation and teacher scoring both use thinking off. All four distributions p, r, q and s share that mode, so the checkpoint comparison does not also change thinking mode. The original student-off/teacher-on recipe remains a separate compatibility check. Evaluation also uses thinking off, with the 16,384-token response cap.

At initialization, θ=φ₀, so K=0 and the key arms collapse. First produce a common θ₆₄ using 64 raw worked-solution OPSD updates, then branch every arm from that checkpoint with fresh identical optimizer state. Keep φ₀ frozen. The conclusion is conditional on this warm-up history; it is not a universal statement about teacher age.

For the unchanged baseline, skip optimizer steps entirely. A nominal zero loss with inherited Adam moments can still change parameters. In diagnostics, identical weights and identical no-PI prefixes must give zero correction within numerical tolerance.

What will decide the next experiment?

PI utility

For each context and block, predict U_context−U_noPI using features measured before adaptation. Start with two predeclared PI features: mean full-vocabulary D_KL(q_c || r) and its difference between correct and incorrect initial student responses. Record that the latter is unavailable for all-correct/all-incorrect blocks; keep those blocks. Compare against difficulty, response length/cap rate, raw OPSD divergence D_KL(q_c || p) and checkpoint drift. Token curves and entropy/EOS changes are secondary diagnostics.

In this eight-block batch, plot paired outcomes and estimate variance; do not fit and announce a successful selector. A later, separately reviewed study needs new discovery and held-out blocks, a frozen low-capacity predictor, grouped validation, and a comparison of its chosen PI against fixed worked-solution PI and a compute-matched random choice. Training and evaluation of the selector must not reuse outcome labels.

Checkpoint effects

Report B10−B11, BS−B11 and the full factorial contrast, plus every arm's absolute accuracy, response length, cap rate, entropy and pre/post-clipping update norms. If transported PI wins, inspect a development-only matched-update-norm comparison before concluding the checkpoint anchor is harmful. If synchronized PI wins, distinguish freshness from amplification or collapse before testing EMA.

Pair by problem, sampling seed and adaptation block. Resample whole adaptation blocks and benchmark problem groups, retaining shared controls, all arms and all checkpoints together. The same 100 benchmark questions appear in every block; do not treat these panels, tokens, eight responses or duplicated cross-node controls as independent problem samples. Report feasibility intervals as exploratory. In confirmation, report training seeds separately and use paired problem-group uncertainty with prespecified multiplicity control for B10−B11 and BS−B11.

A +2 percentage-point target is a desired practical effect, not a power guarantee. For illustration, a paired comparison with discordance 0.20 needs roughly 3,920 independent questions for 80% power at two-sided 5% significance to detect 0.02, before clustering or multiple comparisons. Estimate actual discordance and training variability from the pilot before sizing confirmation.

Conditional next stage, after reviewing feasibility

Run two independent follow-ups concurrently: A expands PI-utility prediction to new blocks; B runs longer checkpoint comparisons. Replicate selected comparisons at training seeds 29 and 43 with their own common warm-ups and swapped node assignments. Freeze the loss, prompt, length and selection rules before consuming final test. Retain the three-benchmark, eight-response monitoring protocol at each 10% milestone, with costs recalculated for the new run length. A final selector/generalization claim needs fresh evaluation data that were not used to choose methods; the repeatedly monitored benchmarks cannot supply that independent evidence. Add a separately pinned retention panel before claiming general improvement.

Only then move to code transfer, MOPD routing, an RL-trained PI generator, teacher EMA schedules, or a larger publicly available reasoning model.
