Read the CRISP instructions, Miles instructions, and the applicable style rules before editing. Keep experiment changes in focused commits after the baseline import. Do not copy another training engine into the original paper's workspace/ tree.

Publish explicit, focused commits directly to origin/main. Preserve each commit; do not squash or force-push. Create a pull request only if the user explicitly requests one. This publication workflow does not change the separate requirement to review the experiment plan before a full run.

Research protocol remains under review

Public code and reports use generic worker labels and configurable paths. Real user identities, personal paths, hardware codenames, hostnames, cluster or reservation identifiers, private endpoints, credentials, and raw runtime logs belong in ignored local configuration. Review new file contents and Git metadata before pushing. Required upstream attribution remains intact.

Read the OPSD implementation and reference-validation design first. It proposes porting the original full-vocabulary loss with a frozen base teacher and canonical LoRA, then validating loss, gradients, identical-token model updates and distributed reduction against the pinned author repository. This supersedes the earlier sampled-token implementation proposal. The existing Miles OPD signal is a different objective and remains separate.

The later scientific study separates PI corrections from checkpoint differences and measures actual unhinted student learning. Its run matrix and compute budget must be revised after the reference-validation pilot; the earlier sampled-token cost projection does not cover this port.

This change establishes the source baseline and development location. It does not add the PI scorer, change the loss, install dependencies, or launch training. The existing upstream examples are reference implementations, not approval to start a full run. A bounded pilot and a full study have separate review gates.

Validation for the import checks the upstream Git tree against the tracked copy, including executable bits and symlink targets, and verifies that no nested Git repository or submodule was introduced. Runtime correctness of later experiment patches requires their own tests.
